# AI Usage

This project was built with heavy AI assistance. I directed the work, reviewed each phase plan and result, and tested parts of the UI by hand, but most of the code text was generated by AI, not typed by me.

## Tools used

- **Claude Code**: wrote the code, tests, migrations, Docker files and docs, one phase at a time.
- **Claude (chat)**: helped me analyse the brief, split it into phases, write the Claude Code prompts, and review each plan before I approved it.

## Bugs the process caught

- A follow-up sent with a non-UTC offset was echoed back un-normalised. Now normalised in the schema, with a test.
- A SQLite batch migration dropped the `DESC` ordering of a composite index. A test exposed it and the migration now restores it.
- Relative-time rendering risked a hydration mismatch. The clock hook now returns nothing until after mount.
- The seed's `--reset` left stale session objects. Fixed in its own commit.
- The component generator imported its class-name helper from an unwanted package. Replaced with the standard local helper.
- QA found that focus fell to `<body>` after saving a note, long unbroken text overflowed the dialog, and a failed refetch wiped the cached timeline. All fixed.

## What I tested myself

I ran the app in the browser and checked the lead list and grouping (Today, Overdue, Upcoming), the timeline dialog, follow-up validation, and adding a note with a follow-up.

The wider end-to-end checks (all filters, search, add lead, error states, accessibility, responsive layouts) were run by an AI-driven Playwright audit, not by me by hand.

## Disclosure

AI wrote most of the implementation. I did not review every line. Tests, lint and builds were run before every commit. I am happy to walk through the design decisions and the key code paths in the interview.
